# Engineering Debrief

The framework consumes current PracticeResult, inspects actual objectives and selects a failed critical constraint by the Mission family. It never ranks unlike units using an invented penalty score. Every Mission has a distinct rule and supported control mapping.

**Directly Observed**: actual satisfied/failed objective values, computed bottleneck/times, maximum recorded path-loss contribution, worst channel, Monte Carlo pass count and executed manufacturing station totals.

**Model-based Explanation**: original completion-time envelope, valid topology/path requirements, package power scope, received/margin equations, Gaussian pitch/offset relationships, shared and independent variation, Known-Good/test/rework event scope.

**Suggested Experiment**: a player-controlled decision change with other inputs fixed; equal Seed/Samples for statistical comparisons. No new simulation, counterfactual optimizer or API is hidden behind the explanation. Multi-factor changes are explicitly possible influences rather than a proven single cause. Component choices may bundle existing model presets, and this scope is stated.

Stale results cannot generate a current Debrief. Numerical data are read from original result ledgers; unsupported physics never receives a fabricated value. Educational Assumption is retained, including in PASS cases. Suggested actions do not guarantee pass or real manufacturing performance.
