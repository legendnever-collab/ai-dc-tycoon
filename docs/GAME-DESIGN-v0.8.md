# From Prototype to Production

Chapter6 adds Missions16–18 without rewriting Chapters1–5. EVENT → CHOOSE → BUILD → SIMULATE → DIAGNOSE → OPTIMIZE → RESULT → REWARD remains the loop. The customer requests repeatable assembly, then a real simulated pilot batch. Controls select an equipment/architecture/process recipe, not an arbitrary optical performance boost.

M16 compares Edge-like, Direct and Evanescent Preview at the same customer alignment window and interface budget. M17 starts with 0.48µm pitch mismatch plus Basic equipment variation; precision alone leaves an edge-channel problem. Precision + Pitch Matching is one affordable diagnosis-based solution. Active equipment is deliberately outside M17's260-credit allocation when paired with matching.

M18 has Prototype First, Quality First and Cost & Volume orders. Cheap/fast equipment can meet the small Prototype order, whereas quality requires channel coverage. Known-Good pre-test can reduce late expensive assembly scrap but adds fixtures/testing. Rework improves alignment only. Final testing can miss localized failure with Basic aggregate scope. Actual-good accepted units and observed shipped units remain distinct.

Credits and XP preserve the original campaign reward system. Engineering allocations and customer-funded batch budgets use the same educational Credits unit; hypothetical pilot expenditure is tracked inside the scenario ledger, not repeatedly debited from the legacy campaign purse. Equipment selected is charged in setup and affects sigma/time in every run, including unused stations. First-clear rewards300/150,450/200,600/250(XP/Credits) are unique; retries preserve seed and are not permanently bankrupted by stochastic failure.
